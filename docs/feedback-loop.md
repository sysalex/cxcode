# 反馈循环机制

Harness Engineering 不是一次性文档，而是持续循环。

## 开发循环

```text
读取上下文 -> 制定计划 -> 实现 -> 运行门禁 -> 修复 -> 重新验证 -> 更新文档
```

## 质量门禁循环

```text
门禁失败 -> 查看输出 -> 定位原因 -> 修复根因 -> 重新运行
```

除非 `docs/quality-gates.md` 明确允许临时例外，否则不能绕过失败门禁。

## 运行时循环

```text
告警/日志/故障 -> 分诊 -> 复现 -> 修复 -> 测试 -> 发布 -> 复盘
```

每次生产故障至少要产生以下一种改进：

- 增加测试
- 调整告警
- 更新 runbook
- 增加架构约束
- 编写 ADR

## 架构漂移循环

```text
发现漂移 -> 分类 -> 修正代码或更新 ADR -> 增加机械化检查
```

漂移示例：

- 非法 import
- 领域层依赖框架
- 敏感操作缺少审计事件
- API 行为未写入契约
- 状态流转绕过状态机
