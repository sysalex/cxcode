# 非功能需求

以下目标在生产前必须进一步量化。

## 可靠性

- 考试过程必须能容忍浏览器刷新。
- 自动保存必须可重试。
- 提交必须幂等。
- 超时提交必须能和手动提交安全收敛。
- 关键审计事件写入必须被监控。

## 性能目标

初始目标：

- 自动保存接口在预期负载下 p95 小于 300ms。
- 提交接口在预期负载下 p95 小于 500ms。
- 正常情况下，考试页面刷新后 3 秒内恢复作答。
- 活跃考试看板 5 秒内更新。

最终目标必须根据预期并发考生人数确定。

## 可用性

- 活跃考试窗口属于发布敏感期。
- 维护窗口必须避开已排期考试。
- 健康检查必须覆盖 API、数据库、缓存、队列和审计事件落点。

## 可访问性与兼容性

- 考生关键流程必须支持键盘操作。
- 错误信息必须可见且可执行。
- 生产前必须明确支持的浏览器。
- 除非考试策略明确禁止移动设备，否则小屏设备不能阻断考试完成。

## 容量规划

生产前必须定义：

- 最大并发考生数
- 自动保存间隔
- 单份试卷题目数量
- 答案 payload 大小
- 数据库写入吞吐
- 审计事件吞吐
