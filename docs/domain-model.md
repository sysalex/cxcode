# 领域模型

## 聚合

### 考试 Exam

负责考试时间、规则、参与资格和发布状态。

业务不变量：

- 考试结束时间必须晚于开始时间。
- 考生不能在允许开始时间之前进入考试。
- 考生不能在服务端最终截止时间之后继续提交，超时提交流程除外。
- 有进行中作答时，考试规则不能被随意修改；必须通过明确的修正流程。

### 试题 Question

负责题干、答案结构、评分信息、标签和版本。

业务不变量：

- 已发布试题版本不可变。
- 试卷必须引用不可变的试题版本，不能引用可变草稿。
- 答案 key 不能暴露给考生。

### 试卷 Paper

负责分配给考试或作答的不可变题目集合。

业务不变量：

- 已分配给进行中作答的试卷不能改变。
- 随机组卷结果必须可通过已存储的数据复现。

### 作答 Attempt

负责考生参与记录、考试时间、状态和提交关系。

业务不变量：

- 考生的作答次数不能超过考试规则允许的次数。
- 作答状态必须遵守 `docs/state-machines.md`。
- 开始、超时和最终提交都以服务端时间为准。

### 答卷 AnswerSheet

负责保存答案和版本信息。

业务不变量：

- 只有作答进行中时才能修改草稿答案。
- 已提交答案不可变。
- 自动保存必须具备幂等性，并处理版本冲突。

### 成绩 Grade

负责分数、反馈、阅卷人和发布状态。

业务不变量：

- 只能为已提交答卷生成成绩。
- 发布成绩必须产生可审计记录。
- 考生可见结果不能暴露内部阅卷备注。

## 领域事件

- `exam.created`
- `exam.scheduled`
- `exam.started`
- `attempt.created`
- `attempt.resumed`
- `answer.auto_saved`
- `answer.save_failed`
- `exam.submitted`
- `exam.timeout_submitted`
- `grading.completed`
- `result.published`
- `proctoring.violation_detected`

用于审计或系统集成的领域事件必须稳定，并具备版本管理策略。

## 领域服务

当行为不自然属于单个聚合时，才使用领域服务。例如：

- 考试资格策略
- 组卷策略
- 超时提交策略
- 阅卷策略
