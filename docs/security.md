# 安全与权限模型

## 安全原则

- 默认拒绝。
- 所有非公开请求必须认证。
- 所有领域操作必须授权。
- 权限判断以服务端为准，不能只依赖前端隐藏按钮。
- 考试开始前不得泄露试题内容。
- 答卷、成绩、审计日志都属于敏感数据。

## 角色

- 管理员
- 教师
- 考生
- 监考员
- 审计员

角色判断不等于数据权限判断。必须同时校验资源归属和作用域。

## 必须具备的权限检查

- 考生只能访问分配给自己的考试。
- 考生只能访问自己的作答和成绩。
- 考生不能访问答案 key。
- 教师只能管理自己组织或授权范围内的考试。
- 教师不能直接修改已用于正式试卷的不可变试题版本。
- 监考员只能查看被分配考试的监考数据。
- 审计员可以读取审计记录，但不能改变考试状态。

## 威胁模型

至少覆盖：

- 考前泄题
- 跨考生访问答卷
- 重复或伪造提交
- 客户端篡改倒计时
- API 重放攻击
- 权限提升
- 参数批量赋值漏洞
- 日志泄露敏感信息
- 活跃考试期间执行危险数据库迁移

## 审计事件

以下动作必须审计：

- 登录和登录失败
- 权限拒绝
- 考试创建、排期、取消、关闭
- 作答开始和恢复
- 自动保存失败
- 手动提交
- 超时提交
- 成绩定稿
- 成绩发布、修正、撤回
- 试题版本发布
- 角色或权限变更
